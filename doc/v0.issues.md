# Issues: V0 — Работающий сквозной пайплайн

Порядок соответствует зависимостям (issue ниже обычно требует issue выше). Метки: `foundation`, `codegen`, `math`, `thermo`, `validation`, `docs`.

---

### #1 — Схема описания топологии колонны

**Метки:** `foundation`

**Описание.**
Определить формат (JSON или YAML) для описания структуры ректификационной колонны: список ступеней, тип каждой ступени (`feed` / `simple` / `condenser` / `reboiler` / `side-draw`), параметры фида (ступень подачи, состав, расход, температура), число и идентификаторы компонентов, параметры Antoine для каждого компонента.

Пока без учёта требований codegen (unroll, SoA и т.п.) — только то, что нужно для однозначного описания MESH-задачи.

**Критерии проверки:**
- [ ] Написана спецификация схемы (markdown или JSON Schema) с примером на 5 ступеней × 2 компонента
- [ ] Схема покрывает все типы ступеней, перечисленные в основном плане
- [ ] Пример проходит валидацию (если используется JSON Schema) или ревью вручную
- [ ] Зафиксировано решение JSON vs YAML с кратким обоснованием (1 абзац)

### #3 — Формулировка MESH-уравнений (Naphtali-Sandholm)

**Метки:** `math`

**Описание.**
Зафиксировать на бумаге/в доке точную систему уравнений (Material balance, Equilibrium, Summation, Heat balance) для каждого типа ступени в формулировке Naphtali-Sandholm — то, что кодогенератор будет превращать в код. Явно выписать неизвестные и уравнения по ступеням.

**Критерии проверки:**
- [ ] Есть документ/раздел с полным выводом уравнений для всех типов ступеней
- [ ] Размерность системы (число уравнений = число неизвестных) явно посчитана и сходится для тестового кейса 5×2
- [ ] Документ проверен вручную на маленьком кейсе (например, 3 ступени) — согласованность индексов и уравнений

### #4 — Модуль термодинамики: Antoine + ideal Raoult

- [ ] Явно задокументировано ограничение скоупа (идеальность, только Antoine) — понадобится для главы "Scope" в дипломе

### #5 — Наивный кодогенератор C99 (без оптимизаций)

**Метки:** `codegen`

**Описание.**
Реализовать транслятор из внутреннего представления (#2 + #3) в компилируемый C99-код: генерация функции невязки MESH-системы и обвязки (объявление переменных, вызовы термо-функций из #4). Без unroll, без SIMD, без SoA, без устранения диспетчинга — простейший рабочий вариант, возможно даже с `if`/switch по типу ступени в рантайме.

**Критерии проверки:**
- [ ] Генератор принимает результат парсинга топологии и выдаёт `.c`/`.h` файлы
- [ ] Сгенерированный код компилируется без warnings на `-Wall -Wextra` (или задокументированы и объяснены оставшиеся warnings)
- [ ] Код детерминированно регенерируется (повторный запуск на том же входе даёт идентичный вывод) — важно для воспроизводимости эксперимента

### #7 — Dense LU solver и цикл Ньютона с line search

**Метки:** `math`

**Описание.**
Реализовать решение линейной системы (якобиан × Δx = -невязка) через dense LU-разложение (можно использовать существующую библиотеку типа LAPACK для baseline — специализация будет позже, в V1) и обернуть в итерационный цикл Ньютона с line search (damping) для расширения области сходимости.

**Критерии проверки:**
- [ ] Цикл Ньютона доходит до сходимости на тестовом кейсе 5×2 за разумное число итераций (задокументировать сколько)
- [ ] Line search реализован и включаем/выключаем флагом (для последующей проверки, что без него хуже — не обязательно сейчас, но полезно для V2)
- [ ] Есть критерий остановки (норма невязки < tolerance) и защита от бесконечного цикла (max iterations + явный статус `Converged: yes/no`)
