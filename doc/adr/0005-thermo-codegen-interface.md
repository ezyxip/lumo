# ADR-0005 Общий интерфейс термодинамики для MESH

**Статус** принято

## Решение

Компилятор выбирает генератор по термодинамической модели из входа v1
У каждой модели свои шаблоны C99 и свои параметры
Полученный код включается в расчётную программу вместе с MESH и решателем

Общая функция `lumo_thermo_eval` принимает температуру, давление и мольные
составы жидкости и пара
Она возвращает невязки фазового равновесия, молярные энтальпии двух фаз
и статус вычисления
Суммирование долей и балансы остаются в MESH

Невязки выбраны вместо обязательного интерфейса коэффициентов K
Это позволяет следующей модели выражать равновесие своей формулой,
например через фугитивности
Общий контракт пока ограничен одной жидкой и одной паровой фазой

Первой реализацией служит Antoine + Raoult с идеальными энтальпиями
и постоянными теплоёмкостями компонентов
Она принимает явные параметры `inline`, проверяет единицы и диапазоны
и встраивает константы в сгенерированный код
Разрешение ссылок на справочник является отдельным шагом до генерации

Для подготовки питания добавлена функция `lumo_thermo_flash`
Она принимает общий состав, давление и одно из трёх описаний состояния
и возвращает температуру, долю пара, составы фаз и энтальпию питания
Алгоритм flash принадлежит конкретной модели термодинамики
В текущей идеальной модели он использует внутренние K и Rachford–Rice
Модуль подготовки входов не обращается к коэффициентам Antoine напрямую

## Связь с прежними решениями

Для v1 это решение уточняет интерфейс из ADR-0001
Функции давления насыщенного пара и коэффициентов K больше не являются
обязательным внешним контрактом каждой будущей термодинамической модели

Реализация и правила вызова описаны в
[codegen/thermo](../../codegen/thermo/README.md)
