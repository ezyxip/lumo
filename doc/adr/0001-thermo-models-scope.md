# ADR-0001: Термодинамика — Antoine + ideal Raoult в V0, точка расширения через thermo.model

**Статус:** принято
**Дата:** 2026-09-11
**Контекст:** ишью #2 (парсер топологии), #4 (модуль термодинамики)

## Контекст

Формат входа компилятора (`compiler_input.json`, схема в `examples/schema/`) содержит
константы уравнения Антуана у каждого компонента и поле-дискриминатор
`thermo.model` со единственным допустимым значением `antoine_raoult`.

При реализации парсера топологии (ишью #2) встал вопрос: жёстко ли зашивать
термодинамику в структуру внутреннего представления компилятора, и не
преждевременно ли это.

## Решение

1. **В V0 термодинамика Antoine + ideal Raoult жёстко зашита в формат входа
   и внутреннее представление.** Поля `antoine` лежат прямо в структуре
   компонента, валидатор принимает только `thermo.model = "antoine_raoult"`.

2. **Точка расширения — поле `thermo.model`.** Оно является дискриминатором
   термодинамической модели. Новые модели добавляются расширением формата
   (новые поля у компонента/в `thermo` + новое значение дискриминатора),
   без переделки пайплайна.

3. **Интерфейс генерируемого кода — фиксированный.** Сгенерированный C-код
   (ишью #5) вызывает термо-функции (ишью #4) через стабильный интерфейс
   вида `Psat_i(T)`, `K_i(T, x)`. Смена термодинамической модели — это другая
   реализация этих функций, а не переделка кодогенератора.

## Обоснование

- Antoine + Raoult — зафиксированное ограничение скоупа V0 (README,
  `doc/thesis_features_full.md`): бинарные смеси, идеальность, NRTL/UNIQUAC/PR-EOS —
  Future Work. Это осознанное упрощение для дипломного эксперимента, а не недосмотр.
- Строить сейчас абстракцию «термо-модель как плагин» ради V0 — преждевременная
  архитектура. Дешевле сломать формат входа один раз, когда появится реальная
  вторая модель.

## Последствия

**Положительные:**
- Парсер и структуры данных V0 минимальны, без лишних слоёв абстракции.
- Формат входа уже содержит дискриминатор — добавление модели не потребует
  ломающего изменения схемы в части уже существующих полей.

**Отрицательные / принятые риски:**
- Модели, где параметры не привязаны 1:1 к компоненту (например, бинарные
  interaction-параметры NRTL — парные, а не покомпонентные), потребуют
  **ломающего изменения** структуры `Config` и формата входа.
- Примеры в `examples/` (01–03) при таком изменении потребуют миграции.

## Ограничение скоупа (для главы "Scope" диплома)

Единственная поддерживаемая термодинамическая модель в V0 — Antoine + ideal
Raoult (`thermo.model = "antoine_raoult"`). Давления насыщенных паров считаются
по уравнению Антуана (`lg P = A − B/(C + t)`, P в мм рт. ст., t в °C), константы
фазового равновесия — по закону Рауля для идеальных смесей. Неидеальность
(NRTL/UNIQUAC/PR-EOS), многокомпонентные смеси (более 3) и переменное давление
— вне скоупа V0.
