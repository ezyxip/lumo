# Lumo

Компилятор MESH-моделей ректификационных колонн: принимает описание колонны и генерирует специализированную исполняемую модель на C99, решающую MESH-уравнения методом Ньютона.

Сам компилятор пишется на Go. Сгенерированный код — C99 без внешних рантайм-зависимостей, пригодный для встраивания, edge-контроллеров и задач оптимизации, где нужны тысячи дешёвых вызовов модели.

Минимальная задача: рассчитать разделение бинарной смеси в идеализированной колонне в установившемся режиме — составы продуктов, профили по ступеням и тепловые нагрузки. Входные данные, результаты и границы ответственности зафиксированы в [концептуальной постановке](doc/scope.md).

## Зачем

Существующие подходы не закрывают нишу между двумя полюсами:

- **Generic symbolic codegen** (CasADi и подобные) — умеет генерировать код и считать производные, но не знает специфику MESH-структуры (блочная трёхдиагональность якобиана, типы ступеней, топология конкретной колонны).
- **Domain-aware runtime** (Aspen, gPROMS, DWSIM, ChemSep) — знает структуру MESH-задачи, но исполняет её через generic runtime (sparse LU с анализом структуры на каждый прогон), а не через codegen под конкретный экземпляр колонны.

Lumo эксплуатирует заранее известную структуру задачи на этапе компиляции — как на техническом уровне (специализация под топологию, без рантайм-диспетчинга), так и на математическом (структура якобиана, метод решения). Подробнее — в [тезисах](doc/thesis_features_full.md).

## Как работает

Задача разделена на два уровня:

- **Уровень 1 — компилятор:** `compiler_input.json` (компоненты, число ступеней, топология, давление) → сгенерированная модель. Меняет размерность и связность MESH-системы, требует перегенерации.
- **Уровень 2 — модель:** `model_input.json` (питание `F, z, q`, спеки продукта `R, D`, начальное приближение) → `model_output.json` (профили `T, x, y, L, V` по ступеням, продукты `D, W, Qd, Qw`, диагностика сходимости).

Новый контракт данных — [v1](examples/v1/README.md): [JSON-схемы](examples/schema/v1/), [Go-типы](contracts/v1/types.go) и пример входов. Парсеры и валидаторы обоих входных файлов находятся в [contracts/v1](contracts/v1/README.md)
Пакет `topology` сохраняет чтение прежнего формата из [examples/README.md](examples/README.md) и не используется генераторами

## MESH-постановка

На каждой ступени решаются MESH-уравнения: материальный баланс (M), равновесие пар–жидкость (E), суммирование долей (S), тепловой баланс (H). Ключевое свойство: постановки Rating (задано флегмовое число) и Design (задана чистота продукта) отличаются ровно одним замыкающим уравнением — остальное MESH-ядро идентично, поэтому компилятор генерирует его один раз и параметризует только последнюю строку якобиана.

Полная формальная постановка — в [doc/problem.md](doc/problem.md).

## Статус и roadmap

Проект в начале пути: сквозной пайплайн (V0) в работе, в качестве эталона используется reference-солвер в `classic-solver/`.

| Версия | Содержание | Статус |
|---|---|---|
| V0 | Сквозной пайплайн: топология → C99 → Ньютон (Naphtali-Sandholm, FD-якобиан, dense LU, line search), кейс 5×2 | в работе |
| V1 | Block-tridiagonal solver, масштабирование по N, точка кроссовера vs dense LU | план |
| V2 | Факторы кодогенерации (специализация, SoA, unroll, SIMD), факторный эксперимент DoE | план |
| V3 | Аналитический якобиан (source-transform AD по Graph IR) vs FD | план |
| V4 | Сравнение с CasADi и DWSIM на общих кейсах | план |
| V5+ | Буфер: precision, quasi-Newton, другие методы MESH, инициализация, PCR, WASM | опционально |

Полный текст — в [doc/roadmap.md](doc/roadmap.md), декомпозиция V0 на задачи — в [doc/v0.issues.md](doc/v0.issues.md).

## Быстрый старт

Пока компилятор в разработке, запустить можно reference-солвер — он считает те же примеры и даёт эталонные данные для будущей валидации кодогенерации:

```bash
uv run classic-solver all --verbose
uv run pytest -q
```

Примеры лежат в `examples/`:

- `01_gubkin_octane_decane` — октан/декан из методички РГУ (13 ступеней, P=0.12 МПа)
- `02_benzene_toluene` — бензол/толуол, 1 атм, канонический идеальный кейс
- `03_synthetic_wide_boiling` — синтетический кейс для теста обусловленности

Подробнее про reference-солвер — в [classic-solver/README.md](classic-solver/README.md).

## Структура репозитория

- `codegen/mesh/` — генератор C99 для функции невязок колонны
- `codegen/initialguess/` стартовые профили состояния MESH на C99
- `codegen/prepare/` подготовка питания и режима для MESH на C99
- `codegen/jacobian/` вычисляет якобиан по переданной функции невязки
- `codegen/thermo/` — генератор C99 для Antoine + Raoult и идеальных энтальпий
- `contracts/v1/` — Go-типы нового контракта входов и результатов
- `topology/` — парсер и валидатор прежнего формата
- `doc/` — тезисы, формальная постановка, roadmap и декомпозиция V0
- `examples/` — примеры колонн (compiler/model input/output) и JSON-схемы форматов
- `classic-solver/` — reference MESH-солвер для генерации эталонных данных

## Ограничения скоупа

Упрощённая термодинамика: Antoine + ideal Raoult, бинарные смеси, постоянное давление по высоте колонны. NRTL/UNIQUAC/PR-EOS и промышленная неидеальность — Future Work, см. [тезисы](doc/thesis_features_full.md).
