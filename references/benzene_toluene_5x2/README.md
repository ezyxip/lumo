# Эталон бензол и толуол 5×2

Независимый численный эталон для идеальной модели, задача #9
Результат рассчитан `calculate.py`, это не экспериментальные данные и не результат запуска IDAES или DWSIM
Скрипт не использует Go, C-код, шаблоны, якобиан и солвер Lumo

## Входы и воспроизведение

`compiler_input.json` и `model_input.json` используют контракт v1
Пять позиций включают полный конденсатор 1, равновесные тарелки 2–4 и равновесный кипятильник 5
Питание поступает на позицию 3, давление постоянно и равно 101325 Па
Насыщенная жидкость подаётся с расходом 100 моль/с и мольными долями 0.5 и 0.5
Верхний продукт 50 моль/с, мольное флегмовое число 2.5

```bash
python3 references/benzene_toluene_5x2/calculate.py
python3 references/benzene_toluene_5x2/calculate.py --check
```

Требуется только стандартная библиотека Python 3
Первая команда пересчитывает `reference.json`, вторая проверяет сохранённый результат без перезаписи
SHA-256 обоих входов включены в результат, изменение входа требует явной регенерации
Не запускайте с `python -O`, проверки используют `assert`

## Физические допущения и источники

Основа постановки приведена в открытой реализации IDAES
Модель [тарелки](https://github.com/IDAES/idaes-pse/blob/main/idaes/models_extra/column_models/tray.py) содержит компонентные и тепловой балансы с равновесием фаз
Модель [конденсатора](https://github.com/IDAES/idaes-pse/blob/main/idaes/models_extra/column_models/condenser.py) описывает полную конденсацию, разделение на флегму и продукт и условие температуры начала кипения
Модель [кипятильника](https://github.com/IDAES/idaes-pse/blob/main/idaes/models_extra/column_models/reboiler.py) описывает равновесные выходы и подвод тепла
Эти ссылки обосновывают постановку, численные результаты IDAES здесь не использованы

[IDAES, Ideal Gases and Liquids](https://idaes-pse.readthedocs.io/en/2.13.0/explanations/components/property_package/general/eos/ideal.html) задаёт идеальное смешение энтальпий фаз и закон Рауля
[NIST Chemistry WebBook, Benzene, Antoine Equation Parameters](https://webbook.nist.gov/cgi/cbook.cgi?ID=C71432&Mask=4&Type=ANTOINE&Plot=on) описывает форму уравнения Антуана и необходимость согласования единиц его коэффициентов
Материалы просмотрены 25 октября 2026 года

В этом кейсе используются идеальные пар и жидкость, постоянные теплоёмкости и отсутствие теплопотерь и перепада давления
При `Tref = 350 K` приняты следующие параметры

| Компонент | A | B | C | CpL, Дж/(моль·К) | CpV, Дж/(моль·К) | ΔHvap_ref, Дж/моль |
|---|---|---|---|---|---|---|
| Бензол | 6.90565 | 1211.033 | 220.79 | 120 | 90 | 30000 |
| Толуол | 6.95464 | 1344.8 | 219.48 | 150 | 110 | 33000 |

Коэффициенты перенесены из существующего регрессионного кейса `codegen/mesh/testdata/nonlinear/case.json`
Они не выдаются за коэффициенты из указанной таблицы NIST, у которой другие единицы и наборы данных
Теплоёмкости и теплоты испарения иллюстративные, температурный интервал кейса 350–390 К
Это проверка реализации принятой модели, она не подтверждает точность описания реальной смеси

```text
Psat_i(T) = 133.3224 * 10^(A_i - B_i / (C_i + T - 273.15))  [Па]
K_i(T) = Psat_i(T) / P
y_i = K_i(T) * x_i
hL(x,T) = Σ x_i * CpL_i * (T - Tref)
hV(y,T) = Σ y_i * (ΔHvap_ref_i + CpV_i * (T - Tref))
```

## Независимый алгоритм

Приведённое ниже сведение балансов и алгоритм подбора реализованы здесь самостоятельно
Это не перенос алгоритма из IDAES

Для заданного состава жидкости температура находится из условия начала кипения
Для заданного состава пара температура находится из условия начала конденсации
Оба уравнения решаются скалярной бисекцией

```text
Σ x_i K_i(Tbubble) = 1
Σ y_i / K_i(Tdew) = 1
```

Внешняя неизвестная только одна, доля бензола в верхнем продукте `xD`
Полный конденсатор задаёт `L1 = R*D`, `V2 = (R+1)*D`, `y2 = xD`
По `y2` определяются температура и жидкий состав тарелки 2
Далее балансы последовательно определяют входящий пар с нижней ступени
В следующих формулах `x` и `y` обозначают доли бензола, `f` равен расходу питания на текущей тарелке либо нулю

```text
c = Lprev + f - Vj
a = c*xj + Vj*yj - Lprev*xprev - f*z
b = c*hLj + Vj*hVj - Lprev*hLprev - f*hF

Lj = Vnext + c
Vnext = a / (ynext - xj)
a * (hVnext(ynext) - hLj) - b * (ynext - xj) = 0
```

Последнее уравнение решается бисекцией по `ynext`, температура и энтальпия входящего пара определяются по точке росы
Так вычисляются тарелки 2–4 и состояние кипятильника
Внешняя бисекция по `xD` замыкает общий компонентный баланс

```text
B = F - D
F*z - D*xD - B*xB = 0
QD = V2*hV2 - (L1+D)*hL1
QW = B*hL5 + V5*hV5 - L4*hL4
```

`QD` положителен при отводе тепла, `QW` при подводе
Расходы пара и жидкости меняются по высоте, допущение постоянных мольных потоков не используется
Скрипт ищет физическую ветвь сканированием `xD` между составом питания и единицей и выбирает первый найденный интервал смены знака
Это специализированный расчёт данного кейса, он не доказывает единственность решения и не предназначен для произвольных колонн

## Проверка солвера Lumo

```bash
python3 references/benzene_toluene_5x2/validate.py
```

Требуются Go, Python 3, Git и C99-компилятор с флагами GCC или Clang
Компилятор выбирается через `--cc` или `CC`, по умолчанию `cc`
Скрипт собирает CLI, запускает генерацию из входного файла, компилирует шесть C-модулей с `driver.c` и запускает расчёт
Две сборки проверяются отдельно, без диагностики и с действующим колбеком
Параметры питания читаются из `model_input.json` и преобразуются в C-структуру через временный `input.h`
Этот адаптер ограничен данным кейсом, общий JSON-интерфейс сгенерированной модели он не реализует

`driver.c` последовательно вызывает подготовку питания, начальное приближение, солвер и конечную невязку
Входом солвера служит сгенерированное начальное приближение, эталонные профили ему не передаются
Проверяются все температуры и составы, расходы, обе тепловые нагрузки, невязки MESH и общие балансы
История эталона не пересчитывается и не перезаписывается

Исходники и бинарные файлы создаются во временном каталоге и удаляются после проверки
Отчёты сохраняются в `validation`, другой путь можно задать через `--output`
При нарушении допуска или ошибке любого этапа команда завершается с ошибкой
Это функциональная проверка, время выполнения здесь не измеряется

[Результат сравнения](validation/report.md) и [полные данные](validation/report.json) сохранены для задачи #10
В JSON также записаны версия репозитория, состояние рабочего дерева, версии инструментов, флаги и хеши входов и сгенерированных файлов
