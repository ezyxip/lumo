# Входные данные v1

Пакет содержит Go-типы, строгие парсеры и семантическую валидацию
для описания колонны и параметров одного запуска

```go
cfg, err := contractv1.ParseCompilerInput(compilerReader)
if err != nil {
    return err
}
if err := contractv1.ValidateCompilerInput(cfg); err != nil {
    return err
}
input, err := contractv1.ParseModelInput(modelReader)
if err != nil {
    return err
}
if err := contractv1.ValidateModelInput(cfg, input); err != nil {
    return err
}
```

Парсинг и валидация являются отдельными шагами, как раньше в `topology`
Парсер отклоняет неизвестные и повторяющиеся поля, `null`, пропущенные
обязательные поля, неверные типы и данные после основного объекта
Названия полей регистрозависимы
Явные нули сохраняются, в том числе коэффициенты Antoine и доля пара

Валидатор собирает найденные проблемы в `*ValidationError`
Массив `Issues` и текст ошибки имеют стабильный порядок
Проверяются поддержанные модели, конечность чисел, ID и номера ступеней,
свойства компонентов, составы, состояния питания и режим
Несколько подач на одну ступень разрешены при разных ID

`ValidateModelInput` сначала проверяет описание колонны
Затем проверяет точное совпадение наборов ID подач и компонентов
Расходы питания переводятся в общий базис с учётом состава и молярных масс
Молярный расход дистиллята сравнивается с суммарным молярным питанием,
массовый с суммарным массовым питанием
Состав дистиллята не предполагается известным
Эти проверки не гарантируют существование решения или сходимость

Для `builtin` проверяется форма ссылки, существование записи и согласованность
свойств потребуют справочника, который пока не реализован
Генераторы принимают только разрешённые свойства `inline`
Перевод состояния питания в энтальпию реализован в [codegen/prepare](../../codegen/prepare/README.md)
Поддержка массового расхода дистиллята в решателе остаётся отдельной задачей
Парсер и валидатор выходного `ModelOutput` в этот API не входят

`topology` больше не нужен генераторам v1
Он пока сохранён для старых примеров, автоматического преобразования между
форматами нет

## Проверка

```bash
go test ./contracts/v1
```

Тесты используют опубликованный пример с `builtin` и отдельную копию
синтетических свойств из нелинейного теста MESH
Свойства `inline` предназначены для проверки модели и не являются
экспериментальным набором теплоёмкостей и теплот испарения
