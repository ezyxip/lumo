# Генерация невязок MESH

`Generate` принимает описание колонны v1 и возвращает шесть файлов C99

```text
lumo_mesh.h
lumo_mesh.c
lumo_thermo.h
lumo_thermo.c
lumo_jacobian.h
lumo_jacobian.c
```

Поддержаны полный конденсатор, равновесный кипятильник, постоянное давление
и замыкание по молярному флегмовому числу
Число компонентов и места подач задаются при генерации
Свойства компонентов должны быть разрешены в `inline`

## Сверка с референсом

Общая постановка сверена с Part C приложения к работе Peccini et al
[Globally Optimal Distillation Column Design using Set Trimming and Enumeration Techniques](https://www.ou.edu/class/che-design/pub-papers/Supplemental-Globally%20Optimal%20distillation%20column%20design%20using%20set%20trimming%20and%20enumeration%20techniques%28Peccini%20et%20al%29-23.pdf)
Использованы структура MESH, материальные балансы SC-1–SC-3, условия
равновесия и суммирования SC-4–SC-6 и баланс внутренней ступени SC-7
У нас балансы записаны как вход минус выход, без боковых отборов
Равновесие упрощено до идеальной смеси

Дополнительно сверены балансы в исходниках
[тарелки IDAES](https://github.com/IDAES/idaes-pse/blob/main/idaes/models_extra/column_models/tray.py),
[конденсатора](https://github.com/IDAES/idaes-pse/blob/main/idaes/models_extra/column_models/condenser.py)
и [кипятильника](https://github.com/IDAES/idaes-pse/blob/main/idaes/models_extra/column_models/reboiler.py)
Полный конденсатор принят без переохлаждения, при температуре начала кипения
Такой вариант соответствует `TemperatureSpec.atBubblePoint` в IDAES
Это сверка уравнений, а не сравнение результатов двух солверов

## Генерация

```go
files, err := mesh.Generate(cfg)
if err != nil {
    return err
}
for name, data := range map[string][]byte{
    "lumo_mesh.h": files.Header,
    "lumo_mesh.c": files.Source,
    "lumo_thermo.h": files.Thermo.Header,
    "lumo_thermo.c": files.Thermo.Source,
    "lumo_jacobian.h": files.Jacobian.Header,
    "lumo_jacobian.c": files.Jacobian.Source,
} {
    if err := os.WriteFile(name, data, 0644); err != nil {
        return err
    }
}
```

Пример предполагает импорт `os` и `github.com/ezyxip/lumo/codegen/mesh`
Порядок компонентов задан `files.Thermo.ComponentIDs`, подач `files.FeedIDs`

## Вызов C

```c
int lumo_mesh_residual(
    const double *state,
    const struct lumo_mesh_operating *operating,
    double *residual
);
```

Оба массива содержат `LUMO_MESH_SIZE` элементов
`operating` передаёт расход дистиллята, молярное флегмовое число и для каждой
подачи расход в моль/с, полный мольный состав и энтальпию в Дж/моль
Энтальпия питания должна использовать ту же систему отсчёта, что термодинамика

Это внутренний интерфейс вычисления невязок
Перевод расходов и составов и определение энтальпии питания реализованы
в [модуле prepare](../prepare/README.md)
Чтение `model_input.json` в C и сопоставление ID с массивами требуют
отдельного слоя ввода

При успехе возвращается `LUMO_MESH_OK`
Ошибки входа, диапазона температур и численные ошибки имеют отдельные статусы
При ошибке выходной массив сохраняет исходные значения

## Якобиан

Независимый [пакет jacobian](../jacobian/README.md) вычисляет производные
по переданной функции невязки
`mesh` подключает его через адаптер состояния, режима и статусов
Пакет `jacobian` не зависит от `mesh` или термодинамики

Все способы вычисления на стороне колонны используют тип функции `lumo_mesh_jacobian_fn`
Сейчас реализован `lumo_mesh_jacobian_numeric`
Будущие аналитический вариант и автоматическое дифференцирование смогут
использовать ту же сигнатуру, раскладку матрицы и статусы

```c
lumo_mesh_jacobian_fn compute_jacobian = lumo_mesh_jacobian_numeric;
double matrix[LUMO_MESH_SIZE * LUMO_MESH_SIZE];
int status = compute_jacobian(state, &operating, NULL, matrix);
```

Матрица плотная, `matrix[row * LUMO_MESH_SIZE + col]` содержит
производную невязки `row` по неизвестной `col`
Параметры режима при дифференцировании фиксированы
Матрица сохраняет физические единицы невязки и состояния
Масштабирование для решателя выполняется отдельно

Третий аргумент содержит настройки выбранного способа вычисления
Для численного варианта это `NULL` или указатель на `lumo_mesh_numeric_options`
Поле `relative_step = 0` выбирает `cbrt(DBL_EPSILON)`
Массив `variable_scales` задаёт положительные характерные величины неизвестных
в их физических единицах, по умолчанию все равны единице
Шаг равен `relative_step * max(abs(state[col]), variable_scales[col])`

Используются центральные разности
Если одна из проб выходит за диапазон температур термодинамики,
используется односторонняя разность с меньшим порядком точности
Если обе пробы вне диапазона, возвращается ошибка диапазона
Слишком малый шаг, не меняющий число в памяти, даёт численную ошибку

Входные массивы не изменяются
При ошибке матрица может быть заполнена частично, её нужно отбросить
Выходной массив должен быть отдельным от входных данных и настроек
Дополнительная память на стеке растёт линейно с числом неизвестных
Память самой плотной матрицы растёт квадратично
Разреженный формат потребует отдельного расширения интерфейса

## Раскладка вектора

В описании колонны ступени нумеруются от 1 до N, в C от 0 до N−1
Конденсатор и кипятильник включены в N
Размер одного блока равен `2*C+3`

```text
Ступень 0        x[C], y[C], T, L, QD
Внутренняя       x[C], y[C], T, L, V
Ступень N−1      x[C], y[C], T, B, V
После блоков     QW
```

`y` у конденсатора является формальным равновесным составом
Он задаёт условие начала кипения конденсата, реального выходящего пара там нет
Тепловые нагрузки QD и QW являются неизвестными
QD положительна при отводе тепла, QW при подводе

Макросы `LUMO_MESH_X`, `Y`, `T`, `L`, `V` задают смещения внутри блока
`LUMO_MESH_QD` и `LUMO_MESH_QW` являются абсолютными индексами нагрузок
Нельзя интерпретировать слот V первой ступени как поток пара

Строки невязки устроены следующим образом

```text
На каждой ступени     M[C], E[C], Sx, Sy, H
После блоков          L_1 - R*D
```

Для бинарной колонны с пятью ступенями получается 36 неизвестных
и 36 невязок, как в [mesh.md](../../doc/mesh.md)
Невязки пока не масштабируются
M и замыкание выражены в моль/с, E и S безразмерны, H в Вт

## Балансы на границах

```text
Конденсатор
M_i = V_2*y_i2 - (L_1 + D)*x_i1
H   = V_2*hV_2 - (L_1 + D)*hL_1 - QD

Кипятильник
M_i = L_(N-1)*x_i(N-1) - B*x_iN - V_N*y_iN
H   = L_(N-1)*hL_(N-1) - B*hL_N - V_N*hV_N + QW
```

Внутренние ступени связывают входящие и выходящие потоки
На ступени подачи добавляются `F*z_i` и `F*hF`
Несколько подач на одну ступень складываются
Составы и расходы промежуточного вектора Ньютона не нормализуются и не обрезаются

## Проверки

```bash
go test ./codegen/mesh
```

Тесты через общий `ctest` генерируют и компилируют весь модуль
с `-std=c99 -Wall -Wextra -Werror -pedantic`
Проверяются варианты 3×2, 5×2, 3×3, две подачи на разных ступенях и на одной

Для 3×2 задан полный вектор ожидаемых невязок, посчитанный прямой подстановкой
В этом примере `F=10`, `z=(0.4,0.6)`, `hF=200`, `D=4`, `R=2`
Коэффициенты свойств синтетические и дают `K_i=1`
Чистокомпонентные CpL равны `(2,4)`, CpV `(3,5)`, теплоты испарения `(1000,2000)`
Опорная температура равна 300 K

| Ступень | T | x | y | L или B | V или QD | hL | hV | M | H |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 350 | (0.8,0.2) | (0.7,0.3) | 8 | QD=19800 | 120 | 1480 | (−2.4,2.4) | −1704 |
| 2 | 360 | (0.5,0.5) | (0.6,0.4) | 18 | V=12 | 180 | 1628 | (−2.2,2.2) | 4280 |
| 3 | 370 | (0.2,0.8) | (0.3,0.7) | B=6 | V=12 | 252 | 2008 | (4.2,−4.2) | −2568 |

QW равна 19800 Вт
E равно `y-x`, суммы долей и замыкание равны нулю
Например, H второй ступени равно

```text
8*120 + 12*2008 + 10*200 - 18*180 - 12*1628 = 4280
```

Отдельно проверяются нулевая невязка на искусственно построенном состоянии,
суммирование долей, замыкание, знаки QD и QW, неизменность результата при ошибке
и сокращение всех внутренних потоков при суммировании балансов
Синтетические данные проверяют вычисления, а не достоверность разделения реальной смеси
Случаи с постоянными `K=1` вырождены и проверяют только арифметику
Отдельный [нелинейный случай](testdata/nonlinear/README.md) использует разные
температурозависимые K, проверяет ранг якобиана и сравнивает тестовое решение
Ньютона с независимым сокращённым расчётом
Якобиан проверяется сравнением с отдельными конечными разностями и известными
производными балансов, включая границы температур и ошибки настроек
Проверки ранга и Ньютона используют сгенерированный якобиан
Рабочий решатель и валидация по внешнему симулятору ещё не реализованы
