# Солвер MESH

`Generate(cfg)` создаёт `lumo_solver.h` и `lumo_solver.c`
Поле `Files.Mesh` содержит невязку, термодинамику и численный якобиан
Размер системы фиксируется при генерации, состояние и режим передаются при запуске

```c
struct lumo_solver_report report;
int status = lumo_solver_solve(&operating, state, NULL, &report);
```

До вызова `operating` подготавливается через [prepare](../prepare/README.md),
а `state` заполняется через [initialguess](../initialguess/README.md)
При сборке всех модулей общие файлы из `Files.Mesh` записываются один раз
с одинаковым описанием колонны для всех генераторов
Чтение JSON и сериализация результата остаются задачей будущего слоя запуска

## Алгоритм

Вычисляется невязка и якобиан, затем решается масштабированная система Ньютона

```text
r_scaled[i] = r[i] / residual_scale[i]
J_scaled[i,j] = J[i,j] * variable_scale[j] / residual_scale[i]
J_scaled * delta_scaled = -r_scaled
state_next[i] = state[i] + alpha * variable_scale[i] * delta_scaled[i]
```

Для плотной линейной системы используются исключение Гаусса и частичный выбор
главного элемента по столбцу с перестановкой строк
Порог малого элемента равен `64 * DBL_EPSILON` от наибольшего исходного элемента
масштабированной матрицы, поэтому статус вырожденности охватывает и некоторые
плохо обусловленные системы
Схема факторизации соответствует описанию [LAPACK DGESV](https://netlib.org/lapack/explore-html/d8/da6/group__gesv_ga831ce6a40e7fd16295752d18aed2d541.html)
Сама библиотека LAPACK не подключается

Метод Ньютона с поиском шага также описан в [PETSc SNESNEWTONLS](https://petsc.org/release/manualpages/SNES/SNESNEWTONLS/)
Здесь реализован простой вариант с уменьшением шага вдвое

```text
norm = max(abs(r_scaled))
norm_next <= (1 - 1e-4 * alpha) * norm
norm_next < norm
```

Составы и расходы проверяются перед оценкой пробной невязки
Допускается погрешность границ составов `1e-12` и расходов `1e-12 * sum(F)`
Выход за диапазон температур приводит к уменьшению шага
Компоненты состояния не обрезаются и не нормализуются
Сходимость означает достижение допуска по масштабированной невязке
Малость шага сама по себе не считается сходимостью

## Масштабирование и настройки

По умолчанию расходы масштабируются суммарным молярным питанием,
температуры начальными температурами ступеней, составы единицей
Характерный масштаб тепла равен максимуму начальных абсолютных QD и QW
и произведения суммарного питания на характерную начальную энтальпию фаз
Энтальпия для масштаба ограничена снизу единицей

Материальные балансы и замыкание делятся на масштаб расхода,
тепловые балансы на масштаб тепла, равновесие и суммы долей на единицу
Все масштабы фиксируются перед первой итерацией

```c
struct lumo_solver_options options;
lumo_solver_default_options(&options);
options.max_iterations = 100;
options.residual_tolerance = 1e-10;
int status = lumo_solver_solve(&operating, state, &options, &report);
```

Можно передать собственные положительные конечные массивы масштабов
Вместо стандартного численного якобиана можно указать `options.jacobian`
и его `options.jacobian_context`, используя общий интерфейс MESH
Для стандартного численного якобиана автоматически задаются масштабы переменных

Начальные настройки дают 100 итераций, 30 уменьшений шага и допуск `1e-10`
`max_iterations = 0` проверяет только начальное состояние
`max_backtracks = 0` разрешает только полный шаг
Допустимый предел `max_backtracks` от 0 до 1000

## Результат и ошибки

Статусы различают сходимость, неверный вход, ошибку модели, вырожденный якобиан,
неудачный поиск шага, лимит итераций, численную ошибку и нехватку памяти

`state` содержит последний принятый вектор и сохраняется при ошибке
до первого принятого шага
`report` содержит статус, число принятых шагов, число отклонённых проб,
итоговую норму невязки и норму последнего принятого шага
Если начальную норму определить не удалось, она равна `NAN`
`model_status` сохраняет статус ошибочного вычисления модели или якобиана
После принятого шага он сбрасывается в ноль

Для истории можно передать массив через `residual_history` и его размер
через `history_capacity`
Записываются начальная норма и нормы принятых шагов
При заполнении массива запись прекращается, расчёт продолжается
`report.history_count` сообщает число записанных элементов

Входы, настройки, массивы масштабов, история, состояние и отчёт не должны
перекрываться в памяти
Матрица и рабочие векторы выделяются через malloc и освобождаются после вызова
Память растёт как квадрат числа неизвестных, линейное решение как его куб
Это первая реализация для небольших колонн, универсальная сходимость не гарантируется

## Проверка

```bash
go test ./codegen/solver
```

Проверяется вся цепочка подготовки питания, начального приближения и солвера
На независимом эталонном случае сравнивается полный вектор решения
Дополнительно проверяются изменения режима, пять ступеней, три компонента,
несколько подач, различные масштабы, история и остановки с диагностикой
Линейный решатель проверяется системой с известным ответом и перестановкой строк
Есть отдельный случай вырожденной MESH-системы с постоянными K = 1
Это проверка принятой идеальной модели, экспериментальная валидация не выполнялась
