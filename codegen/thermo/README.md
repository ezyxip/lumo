# Генерация термодинамики

`Generate` принимает `contracts/v1.CompilerInput` и возвращает содержимое
`lumo_thermo.h` и `lumo_thermo.c`

Сейчас поддержаны Antoine + Raoult, идеальное смешение энтальпий и
`constant_cp` для свойств чистых компонентов
Параметры задаются через `properties.source = inline`
Генератор проверяет конечность и положительность теплоты испарения
на обоих концах температурного диапазона
Ссылки `builtin` нужно разрешить до вызова генератора, справочник пока отсутствует

```go
files, err := thermo.Generate(cfg)
if err != nil {
    return err
}
if err := os.WriteFile("lumo_thermo.h", files.Header, 0644); err != nil {
    return err
}
return os.WriteFile("lumo_thermo.c", files.Source, 0644)
```

Пример предполагает импорт `os` и
`github.com/ezyxip/lumo/codegen/thermo`
Порядок элементов массивов соответствует `files.ComponentIDs`

## Интерфейс для MESH

```c
int lumo_thermo_eval(
    double temperature_K,
    double pressure_Pa,
    const double *x,
    const double *y,
    double *equilibrium_residuals,
    double *h_liquid,
    double *h_vapor
);
```

`x` и `y` содержат мольные доли компонентов в жидкости и паре
Функция заполняет по одной невязке равновесия на компонент и две молярные
энтальпии смеси в Дж/моль
Размер массивов задан макросом `LUMO_THERMO_COMPONENTS`

```text
t_C = temperature_K - 273.15
Psat_i_Pa = 133.3224 * 10^(A_i - B_i / (C_i + t_C))
e_i = y_i - (Psat_i_Pa / pressure_Pa) * x_i

h_liquid = sum(x_i * CpL_i * (temperature_K - Tref_i))
h_vapor = sum(y_i * (deltaHvap_ref_i + CpV_i * (temperature_K - Tref_i)))
```

Коэффициент перевода mmHg в Pa взят с округлением из
[NIST SP 811](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b9)
Энтальпии используют приближение из [контракта v1](../../examples/v1/README.md)

Суммы долей и материальные и тепловые балансы проверяются отдельно в MESH
Функция принимает конечные промежуточные значения x и y без нормализации
и обрезки, включая отрицательные значения на итерациях Ньютона

При успехе возвращается `LUMO_THERMO_OK`
Неверные входы, выход за температурный диапазон и численные ошибки имеют
отдельные коды из заголовка
При ошибке выходные буферы сохраняют исходные значения
Вызывающий код должен обработать статус, например уменьшить шаг Ньютона

## Шаблоны и расширение

`templates/thermo.h.tmpl` задаёт общий интерфейс для двух фаз
`templates/antoine_raoult.c.tmpl` содержит текущую реализацию
Go встраивает шаблоны через `go:embed` и подставляет константы компонентов
C-код использует стандартную математическую библиотеку и не выделяет память в куче

Для следующей термодинамической модели добавляется своя реализация генерации
с тем же интерфейсом для MESH
Antoine не является обязательной частью интерфейса
Производные и дополнительные фазы в текущий интерфейс не входят

## Проверка

Нужны Go и C-компилятор `cc` с поддержкой C99

```bash
go test ./codegen/thermo
```

Тест генерирует оба файла, компилирует их с
`-std=c99 -Wall -Wextra -Werror -pedantic`, линкует с `-lm` и запускает расчёт

Давление насыщенного пара сверяется с исходной корреляцией воды из
[NIST WebBook](https://webbook.nist.gov/cgi/cbook.cgi?ID=C7732185&Mask=4)
на четырёх температурах в её диапазоне применимости
Энтальпии проверяются на синтетических коэффициентах с известным результатом
Эти коэффициенты не являются набором свойств для инженерного расчёта смеси

Также проверяются влияние давления, обработка ошибок, отсутствие
нормализации промежуточных составов, валидация параметров и воспроизводимость генерации

## Отладка C-проверок

Общая сборка, запуск и C-макросы находятся в [internal/ctest](../internal/ctest/README.md)
Проверки термодинамики находятся в `testdata/check.c` и запускаются отдельными Go-подтестами
Падение одной проверки не мешает запуску остальных
Для численных сравнений выводятся имя проверки, файл и строка, фактическое
и ожидаемое значения, ошибка и допуск
Для кодов возврата выводятся фактический и ожидаемый статусы

При падении тест сохраняет исходники, бинарник, `build.sh` и журналы проверок
Путь к папке выводится в сообщении `C debug artifacts kept in`
Успешные прогоны удаляют временную папку
Чтобы сохранить файлы успешного прогона, задайте `LUMO_CODEGEN_KEEP=1`

```bash
LUMO_CODEGEN_KEEP=1 go test -count=1 -v -run '^TestGenerateAndRunC99$/^enthalpy$' ./codegen/thermo
```

C-код собирается с `-g -O0`
В сохранённой папке можно повторить сборку и запустить конкретную проверку
под GDB, заменив путь ниже на напечатанный тестом

```bash
/tmp/lumo-codegen-.../build.sh
/tmp/lumo-codegen-.../check enthalpy
gdb --args /tmp/lumo-codegen-.../check enthalpy
```

Передача диагностики и ожидаемые падения проверяются в тестах `internal/ctest`
Сохранённые папки после отладки можно удалить вручную
